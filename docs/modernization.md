# 1.1 改进说明

## 已修复的问题

| 旧实现 | 新实现 |
| --- | --- |
| awk 先匹配通用标记，结束标记也触发开始分支，导致后面的容器原有映射丢失 | 用纯 Python 精确识别区块，回归测试覆盖前后条目、重复区块与损坏标记 |
| 以脚本启动 `main.py`，Web 再导入 `main`，产生两份配置与调度状态 | 包入口 `python -m app.main`，将唯一服务实例传入应用工厂 |
| Web 操作读取过期的模块全局变量 | 不可变配置对象，每个任务捕获一次快照，下一任务使用最新配置 |
| 手动与定时更新可并行覆盖同一 CSV、hosts 与历史 | 单任务互斥；重复请求返回 HTTP 409 |
| 测速退出码为 0 就视为成功，可能重用上次 CSV | 每次使用独立临时输出，校验有效行后才发布缓存 |
| 容器更新失败仍可能向前台返回成功 | 聚合逐容器结果，区分成功、部分成功、全部失败 |
| 容器名和 hosts 内容插入 shell 字符串 | Docker 参数使用 argv，固定写入脚本通过 stdin 接收内容 |
| 配置空值恢复默认值，首次启动带有个人容器和域名 | 空值保留，新安装从空目标开始 |
| 配置、历史直接覆盖，日志与备份不断累积 | 配置与历史原子替换，本地及容器 hosts 各保留一个最新备份，日志轮转 |
| Docker 下载漂移的 latest amd64 旧文件名 | 固定 v2.3.5，按架构下载，验证发布摘要并处理压缩包目录 |
| 过时 Python / Flask 和开发服务器 | Python 3.13、固定依赖版本、Waitress、健康检查与 CI |

## 模块边界

- `config.py`：旧配置迁移、规范化、校验和持久化。
- `hosts.py`：不访问系统的 hosts 渲染与区块替换。
- `docker_client.py`：有限时的容器读取、备份、写入与验证。
- `speedtest.py`：独立测速输出、CSV 校验及缓存发布。
- `service.py`：任务状态、快照、互斥、结果聚合、历史与调度。
- `web.py`：HTTP 接口、可选认证、CSRF 和应用工厂。
- `main.py`：日志、服务及生产 Web 服务器生命周期。

管理界面从异步 API 获取状态，保存配置不会触发隐式写入。前端使用浏览器原生能力，无外部 CDN 或前端运行时依赖。

## 后续方向

下面的能力不属于 1.1 已完成范围，应结合真实使用场景逐项验证：

1. 容器重建事件监听与自动补写，处理 Docker 断线重连和事件去重。
2. 多组规则：不同域名组、容器组使用不同优选策略。
3. 按域名测试 HTTPS 可达性，并设计不会频繁切换的回退策略。
4. 新增容器选择器、结果导出和保留期限设置。
5. 提供权限受限的执行代理或其他写入方式，覆盖无 shell、只读文件系统的镜像。
6. 建立版本化、多架构镜像发布流程及升级说明。

当前容器写入采用原文件就地覆盖，以适配 Docker 的 `/etc/hosts` 挂载；这无法提供重命名式原子替换，也无法保证多个容器跨目标事务一致。备份和校验降低故障影响，逐目标结果用于准确说明实际完成情况。容器重启或外部程序并发修改 hosts 仍需重新检查并执行更新。
